# Implementation Plan: Manager Control Hub — Full Integration with Fresh Database

**Branch**: `004-manager-control-hub-integration` | **Date**: 2026-05-14 | **Spec**: `specs/004-manager-control-hub-integration/spec.md`
**Input**: Feature specification from `specs/004-manager-control-hub-integration/spec.md` + user decision: create fresh database matching star-app schema + FloorPlan additions.

## Summary

Create a new InsForge database that matches star-app's existing data model (El Arrocito / Azúcar y Nuez schema: menu_items with weight-based pricing, options, stock; orders with status pipeline; restaurant_settings with theming; restaurants with mode/currency/colors) and enhance it with FloorPlan tables (floor_plans, restaurant_tables with x/y/rotation/shape coordinates, app_modules). Then integrate all 5 FloorPlan modules (floor editor, menu CRUD, pricing, promotions/events, file imports) into star-app's Manager Hub, wiring the mock localStorage repos to the new database.

## Technical Context

**Language/Version**: TypeScript 5.x, React 19
**Primary Dependencies**: @insforge/sdk, @supabase/postgrest-js, lucide-react, TailwindCSS 3
**Storage**: New InsForge project — fresh database, designed to match code
**Testing**: Manual verification through browser, then add vitest tests post-integration
**Target Platform**: PWA web app (mobile-first customer, desktop manager)
**Project Type**: Single-page web app with multiple views
**Performance Goals**: Manager hub section switches under 400ms p95; floor canvas at 60fps
**Constraints**: Must preserve all existing star-app features (customer flow, kitchen, analytics, dine-in); FloorPlan modules supersede overlapping adminApi features; new database must not break existing code
**Scale/Scope**: Single restaurant tenant (Di Pasquale or Azúcar y Nuez) in new database

## Phase Strategy

### Phase A: New InsForge Database
1. Empty "Dond my first project" (2y542jyv) or create fresh InsForge project
2. Define schema matching star-app's data model (see data-model.md)
3. Add FloorPlan tables (floor_plans, enhanced restaurant_tables, app_modules)
4. Seed with "El Arrocito" / "Di Pasquale" demo data

### Phase B: New Data Layer
1. Create `src/data/insforge/` with repos matching new schema
2. Wire existing App.tsx to new client/repos
3. Verify customer flow loads correctly (menu, settings, orders)

### Phase C: Manager Shell + Floor Editor
1. Port floor-editor domain logic from FloorPlan project
2. Port UI components, convert to TailwindCSS + React 19
3. Wire floor plan data to new DB (floor_plans, restaurant_tables)
4. Integrate shell with star-app's mode routing (?mode=dashboard)

### Phase D: Menu CRUD + Pricing
1. Port MenuModule, convert to TailwindCSS + React 19
2. Port PricingModule, integrate into Catalog inspector
3. Wire to new DB repos
4. Deprecate old adminApi.ts menu methods

### Phase E: Promotions/Events
1. Port PromotionsModule + thresholdRules
2. Wire to new DB promos table
3. Deprecate old adminApi.ts promos methods

### Phase F: File Imports
1. Port ImportsModule
2. Wire to new DB import_jobs table
3. Verify upload validation and result reporting

### Phase G: Verification & Cleanup
1. End-to-end test: customer orders → kitchen receives → manager views analytics
2. Remove deprecated adminApi menu/promos code
3. Verify no regressions in customer, kitchen, dine-in, analytics

## Current State Summary
